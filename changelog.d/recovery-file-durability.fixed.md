- The host-mode and deferred-writes recovery files are now synced to disk before they replace the record, and their directory after the rename (with its parent, when the write had to make the directory), except on Windows, where only the file is synced. So a crash leaves the record as it was or the new one, whole. A write that fails before the rename removes its `.tmp` file instead of leaving it beside the record, logs one it can't remove, and fails with an error that names the record and says it was left as it was. A directory sync that fails after the rename is logged, since the new record is already in place.
