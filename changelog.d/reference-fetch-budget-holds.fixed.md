- The reference fetcher's per-server byte budget (an MCPL server's `autofetch.maxTotalBytes`, 1 GiB by default) now holds as it says. Each fetch read the server's total once, before it started, and set the total to that plus its own bytes when it finished. So concurrent fetches, such as the eager path's eight per result, could together go past the budget, and the last to finish overwrote what the others had added. Bytes fetched but not kept were never charged: a payload the workspace couldn't store, one whose digest didn't match, or a download stopped partway, by `max_bytes`, a timeout or the budget. Now each server's total is charged as bytes arrive, kept or not, and every fetch checks it as each piece arrives, so concurrent fetches can't together pass the budget by more than the piece each was reading when it ran out. A fetch the budget refuses, before it starts or partway, now says that the budget isn't renewed while the host runs, so calling again won't change that.
