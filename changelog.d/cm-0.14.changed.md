- Depend on `@animalabs/context-manager` ^0.14.0. A preview, or any compile made with `dryRun`, now leaves the context manager's estimate, its calibration and a pending kv-unified draft's marker indices as it found them. The context manager refuses its state queries (`isReady`, `getPendingWork`, `getHotContextSettings`, `previewContext` and others), its compiles and its writes while its strategy's initialization is pending (inside `switchBranch`, `fork`, `setStrategy` or `ContextManager.open`) or has failed, where it used to answer; a successful `switchBranch` or `setStrategy`, or a restart, recovers it. A document posted twice is stored as two copies under one group id and is now read as two bodies everywhere, so a stored conversation holding one misses the prompt cache once after the upgrade.
- A context-maintenance pass no longer fails as a whole when one agent's readiness can't be read. context-manager 0.14.0 refuses its readiness queries while a strategy's initialization is pending or has failed, and a strategy can refuse on its own, as the autobiographical one does for a branch it hasn't reloaded. That agent's run now records the error, the agent gets its own `context-maintenance-failed` alert (`scope: 'agent'`), and the other agents run. Before, such a throw failed the pass for every agent, with one framework-scope alert. While an operator surgery holds the store, no pass starts and a running pass starts no new tick, and a failure met then is logged without an alert. `getContextMaintenanceSnapshot()` reports such an agent as `ready: false` with an `error`, and a strategy that can't give a progress snapshot reads as having none.
