- A runtime connect or a restart into an id whose connect is still in flight, in either engine, is now refused before it changes anything, with `MCPL server "<id>" has a connect in flight; try again once it settles`. Before, a second connect went ahead beside it, and whichever settled last replaced the other in the registry without closing it. A disconnect of that id now ends the connect in flight and removes whatever it registered. Before, the disconnect removed the server's config and tool prefix, and the connect then registered the server without them, where no call reached it and only another disconnect cleared it.
