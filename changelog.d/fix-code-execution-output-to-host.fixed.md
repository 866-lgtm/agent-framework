- What the commands a `code_execution` script runs write to stdout and stderr now comes back in the script's result, in the order written on each stream, beside the script's own prints: `subprocess` without `capture_output`, `os.system`, and C code writing to file descriptors 1 and 2. It used to reach only the host's log, and a line a command wrote without a newline ran into the runtime's own reply, so the script waited out its time limit. A command with a lot of output now fills the result as the script's own prints do: each stream keeps up to 2,000,000 characters, and a result past 24,000 characters spills to a workspace file, as any result does. The tool's description now says that what the script and the commands it runs print comes back.
- A command a `code_execution` script runs now reads the end of its input at once: its standard input is `/dev/null`. It used to read the runtime's channel from the host, so a command that reads its input, such as `cat`, or `ssh` without `-n`, took the host's messages, and the script failed or waited out its time limit.
- A script that closes or redirects its file descriptors 0, 1 or 2 no longer breaks the interpreter: the runtime's channel to the host has file descriptors of its own, 3 and 4, which no command a script runs is given, and each script starts with 0, 1 and 2 as the host set them. A script's `os.close(1)` used to leave it waiting out its time limit, and its `os.close(0)` sometimes left the next script doing so.
- What a script and its commands wrote before it was stopped now comes back ahead of the message saying why, when it's killed at its time limit, aborted, or its interpreter crashes; it used to be lost. A crash's own text comes back too, and goes to the host's log: a fatal error's, and now a traceback for a segfault or an abort, which faulthandler writes where CPython alone wrote nothing.
- A background script's journal now holds its commands' output too, and a background script that crashes leaves the last of what it wrote, its crash's text included, in the message that wakes its agent, where that read only "python runtime exited unexpectedly".
- A script's prints now reach the host as each line is complete, so a partial line waits for its newline, a flush or the end of the script. Printing costs more than it did: 100,000 short `print` calls took about half a second, against about a sixth of a second before, on a busy machine.
- An interpreter that exits as it starts now says in the result what it wrote to stderr. Output that arrives while no script runs, such as from a command a script left running, reaches the host's log as `stdout while no script runs: …` or `stderr while no script runs: …`, where stdout's used to read `non-protocol stdout line: …`.
