- MCPL inbound handlers, for requests and for notifications (`mcpl/manifestChanged` and `notifications/tools/list_changed` included), contain synchronous throws and async rejections (#186), including channel reconciliation failures after an acknowledgement. Nothing a server sends, and nothing a handler throws or rejects with, ends the host: a rejection reason that can't be printed is reported as one that can.
  - **Each failure emits `mcpl:request-handler-error` and a stderr line.** Its `error` is the handler's own error. A reply write that failed before it is `responseFailure`, and a reply the handler tried to send after one was already attempted is `refusedResponse` (a result, or an error with its code and message): refused, never written. `responseError` is the internal-error reply's own failure, which the stderr line prints too. A failure of the Discord awareness accounting that a tools-list refresh waits on is global: it's reported as `mcpl:server-error` for every connection, as each is recycled.
  - **A request gets JSON-RPC `-32603` "Internal error"** when its handler fails before any reply bytes may have gone out. That's when it attempted no reply, or its reply failed while encoding. A transport write that threw may have sent part of a reply, so it isn't followed by another. The reply carries the standard message, not the handler's own error text, which stays in the trace and stderr. A notification gets no reply.
  - **A request whose method isn't a string,** or isn't one the host handles, or whose event nothing on the host listens for, is answered `-32601` "Method not found", with a stderr line. A notification nobody handles is ignored.
  - **Non-object JSON** is ignored before property access, in the handshake reader and in routing, as a non-JSON line already is.
  - **A synchronous failure while dispatching an inbound message**, buffered plane flushes and a server's stderr lines included, is reported without interrupting later messages. Its `mcpl:server-error` names the event or method, the request id, and the cause.
  - **A failed write to a stdio server's stdin** (a child that has just exited) is reported instead of ending the host.
  - **A response that can't be encoded** says why in its error (a BigInt, a circular structure, a throwing `toJSON`).
  - **A reply to a connection that has already closed** is dropped without a trace, on either transport, as before.
