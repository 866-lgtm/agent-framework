- MCPL references (RFC-005): display labels now drop the Arabic letter mark (U+061C) along with the other bidi controls. `fetch_reference` shows the response's `Content-Type` and the server's claimed type as labels too, and `save_recent_image` shows a reference's claimed type in its refusal, and an attachment's media type in its receipt, as labels. The stub leaves out a label that sanitizes to nothing. A server's type such as `constructor` now saves the file as `.bin` instead of naming it with inherited function text.
- An `expiresAt` rejected as a field (past its 64-character maximum, or not a string, null included) now fails closed like an unparseable one on the fetcher's paths: `fetch_reference`, the eager default and a code-execution script's result. The fetcher treats such a reference as already expired, never as immortal, and doesn't fetch it. It still serves a copy saved earlier while the host holds the reference's record; a restart or an eviction drops the record, and then the expiry decides. A uri-form image or audio block that a converter hands the provider as a URL source is unchanged.
- An expired reference's stub, `save_recent_image`'s refusal of it and the fetcher's refusal say which case it is: an expiry that has passed, one that doesn't parse, or one rejected as a field. The stub and `save_recent_image` no longer advise `fetch_reference` for it. An expired reference no longer takes one of a result's eight eager-fetch slots, and neither does a second block for a uri the result already listed.
