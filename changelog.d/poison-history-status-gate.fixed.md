- The poison-history breaker sheds history only for an `invalid_request` that came back as HTTP 400, 413 or 422, or that carries no status. The status is a heuristic for when shedding the newest exchange may help, not proof that the history is at fault. 400 and 422 are how a provider answers a request that fails its validation, as a history it can't accept does. A 413 is the request's size, usually from the newest exchange, such as an oversized attachment, and nothing else in the framework recovers it. Other statuses keep the history, since shed history can't be got back and no shed fixes them: a 404 is a model that doesn't exist, and 405, 409, 410 and 415 are about the HTTP request or the resource rather than the conversation. The failure is still counted, logged and reported hard-down either way.
  - As membrane 0.5.86 classifies them, Anthropic files only a 400 as `invalid_request`, and the chat adapters file every 4xx, 400 included, as `unknown`, so neither changes. The raw-fetch Responses adapter files every status it doesn't list as `invalid_request`, so it alone produces an `invalid_request` at 413 or 422 today: a 404, 405, 409, 410 or 415 from it no longer sheds history, and a 413 or 422 still does.
  - From membrane #56 (merged, not yet in a release), one status table serves every adapter. An Anthropic 404 then arrives as `invalid_request`, which is the case this change is for: three failures for a misspelled model would otherwise shed the agent's newest exchanges, with a rewind marker saying the API kept refusing them. A 413 arrives as `context_length` and never reaches the breaker, and a 422 from an OpenAI-compatible server that answers a validation failure with it, such as a FastAPI one, arrives as `invalid_request`. Hosts should take this change before a membrane release that includes #56.
  - An error with no status, from a membrane that reports none, keeps the breaker's earlier rule, the type alone.
  - Anthropic's "credit balance is too low" 400 still arrives as `invalid_request` at 400 and still sheds, until antra-tess/membrane#107, which classifies it as `auth`, is released and in agent-framework's membrane floor.
  - The rewind marker the breaker writes into the agent's context says the model API kept refusing the requests that carried the turns it set aside, and that they were removed so the conversation could go on. It used to say the API kept rejecting the conversation on them.
