- The workspace's tools read a path after its mount's name one way everywhere: `/` between segments, `\` too on Windows, with no empty or `.` segment and no trailing `/`. On a mount without an include, a `..` takes back the segment before it (a mount with an include refuses it). So `work/./a.txt`, `work/a//b.txt`, `work/docs/` and `work/sub/../a.txt` name the workspace entries `a.txt`, `a/b.txt`, `docs` and `a.txt`, the files the disk operations already reached. Before, the workspace's history kept a path as written: `work/a//b.txt` became a second entry for `a/b.txt`, a write to `work/./a.txt` or `work/sub/../a.txt` failed with the store's "Invalid tree path", and a `materialize` naming `work/docs/` found nothing. A `..` with nothing before it to take back climbs above the mount's root and is refused, whatever it reaches afterwards, a path that comes back in by the mount directory's own name included. Before, the traversal guard let that through: a disk read reached the file, and the other tools failed with the store's "Invalid tree path". Its refusal now says `Path traversal detected: "<path>" climbs above the root of mount "<mount>".`, where it said `… resolves outside mount "<mount>"` before, for a climb that left the mount. A separator straight after the mount's name (`work//a.txt`) is refused too, since it would make the rest an absolute path, even where that path lies inside the mount, which the traversal guard let through before: a disk read reached the file, and the other tools found nothing or failed.
  - An entry an earlier version stored under another spelling, such as `a//b.txt` or `c/`, is outside the mount: no tool lists, counts, syncs or writes it, and since no spelling names it, a `materialize` doesn't report it under `skipped`. The workspace's history keeps it as it was. Where such a write reached disk, the file is the one its new spelling names, and the next sync of the mount takes it in. A draft written under such a key that hadn't reached disk when the host upgraded stays in history and never reaches disk. To keep it, read it from the store under its old key, on its branch (`treeGet` on the mount's tree state, `workspace/<mount>/tree`, then `getBlob` with the entry's `blobHash`), and write it again under its new spelling.
