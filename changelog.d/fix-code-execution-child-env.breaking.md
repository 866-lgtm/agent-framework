- **Operators with `codeExecution` enabled:** the python interpreter that runs model-authored scripts no longer inherits the host's environment, and it starts in its own runtime directory instead of the host's working directory. It gets the allowlist stdio MCPL children get (#175): `PATH`, `HOME`, the locale, temp directories, CA bundles and proxy variables, whose URLs can carry credentials. Then come `codeExecution.env`, and last `PYTHONUNBUFFERED=1` and `PYTHONIOENCODING=utf-8`, which the runner sets over any declared value.
  - **What stops arriving:** every host variable outside the allowlist, such as `PYTHONPATH`, `VIRTUAL_ENV`, `PYTHONHOME`, `LD_LIBRARY_PATH`, `PYTHONUTF8` and `ALL_PROXY`, and any credential a script read from `os.environ`. To get one back, list it in `codeExecution.env`, which a recipe can `${VAR}`-substitute from `.env`. `codeExecution.inheritEnv: true` restores the whole environment, and with it hands every host variable, provider keys included, to model code and to every subprocess a script starts.
  - **A script's relative paths** now land in the runtime directory, which goes when the interpreter is reclaimed. A file meant to outlast the interpreter needs an absolute path, or the workspace.
  - **Direct `PyRunner` users:** `PyRunnerOptions` gains `env` and `inheritEnv`, and a runner built without them gets the allowlist.
  - **A misread configuration is refused at create:** an `inheritEnv` that isn't `true` or `false`, such as `"false"`, which would have handed over the whole environment, and an `env` that isn't an object of strings.
  - **Unchanged:** `pythonPath` as given, since a venv's interpreter finds its prefix and site-packages without `VIRTUAL_ENV`, and everything the allowlist passes. The allowlist limits what model code inherits, not what it can read: on Linux a process running as the same user can still read the host's environment through `/proc/<pid>/environ`, and any process can open the host's files by absolute path.
