- A module's event that arrives after `stop()` began is dropped with a log line naming the module, through `ModuleContext.pushEvent()` or the deprecated `queue` handle alike, instead of throwing `Queue is closed`. `stop()` closes the event queue before it stops modules, so such an event comes from a listener that fires while `stop()` runs, or from the module's own `stop()`, where nothing could catch the throw: a module that pushed from its `stop()` made the framework's `stop()` fail. A direct caller of `AgentFramework.pushEvent()` still gets the throw.
