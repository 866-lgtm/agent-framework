- An MCPL server's `inference/request` now gets a result only for an inference that completed with a stop MCPL can name, and the JSON-RPC error otherwise, whether it was streamed or not. A streamed request whose stream failed or stopped early, such as on a timeout, was answered `end_turn` with whatever text had arrived. In XML tool mode, a model that wrote a tool call parked a streamed request's stream, so the request was never answered. Each now gets the error the non-streamed path already sent for a failure, code `-32603` with the cause in its message, and an `mcpl:inference_fail` trace. So does an inference that ended with a stop reason `finishReason` has no value for, which was answered `end_turn`: `refusal`, `tool_use`, `pause_turn`, `abort`, and membrane's guard stops `no_progress` and `round_limit`. In XML tool mode, so does tool-call markup that was answered as a completion: a tool call in a request that isn't streamed, whose markup was returned as content, and, streamed or not, a tool-call block membrane reads no call from or one still open when the output ended, such as a call cut off at `max_tokens`. membrane tells an open block from the text, so a completion that writes `<function_calls>` in prose and never closes it gets the error too.
  - A streamed result carries the response's `finishReason` and `usage`, as one that isn't streamed does. It was always `end_turn` with zero usage, so an answer cut off at `max_tokens` read as finished. Its `content` is the response's text, as a non-streamed result's is, so it no longer includes thinking.
  - Chunks carry only text membrane marks visible: thinking and the text of a tool call are no longer sent as `inference/chunk` deltas.
  - A streamed request's `mcpl:inference_complete` trace now carries `inputTokens` and `outputTokens`. `streamed`, which only that trace carried, is now on every success and failure trace.
