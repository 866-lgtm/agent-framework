- Discord reaction suppression defaults include refusal markers, default/configured awareness markers, and retained recovery-outbox emojis. `framework.getPlacedReactionBaseline()` exposes that snapshot as suppression tokens, converting composite custom-emote markers to stable IDs; stored markers and reaction payloads remain unchanged. Stdio MCPL children get it by default, derived at each spawn (first connect, automatic reconnect, restart). Suppression is by emoji, so members' own reactions with 💤 or the configured awareness emoji stop reaching the agent too, as members' 🛑 already did. A connect or restart that needs the default refuses, before anything spawns or the running child is stopped, when the awareness ledger can't be read, and an automatic reconnect that can't read it fails and retries rather than spawn without the default. Non-blank explicit server env and intentionally inherited baseline values retain precedence, and the framework logs when one replaces the default; a blank value counts as unset. On Windows, duplicate spellings resolve to the first in sorted order within each source, then declared values take precedence over inherited values. Hosts that inject the old refusal-only default must remove that default to adopt the framework-derived one; remote WebSocket adapters still need their own environment configuration (#95).
