- **One spelling per workspace path, on every mount:** a path with `.` or empty segments, a trailing slash, or a `..` that stays inside the mount now reaches the file it names, and answers spell it without them. Before, a store-backed mount refused a `.` or `..` segment with the store's "Invalid tree path", refused an empty segment right after the mount's name as traversal, answered a file's path with a trailing slash with "File not found", and took any other empty segment as given, so a search whose path ended in a slash answered with `//` in each file's path. A `..` is read lexically, as a shell's `cd` reads `link/..`, and a path that leaves the mount is still refused.
