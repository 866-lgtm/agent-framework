- The workspace has an `edit_many` tool: several exact edits, in one file or across files of one mount, stored all or none. Each edit gives `path`, `oldString`, `newString` and `occurrences`, how many times `oldString` must occur (1 when left out), and every occurrence is replaced. Each edit is matched in its file as the call reads it, never in another edit's result, so the list's order doesn't matter, and two edits' matches may touch but not overlap. Matching is `edit`'s. Its input is checked item by item, as every workspace tool's input is checked.
  - Any problem stores none of the call's edits. The refusal names every problem it finds, in edit order, each by its edit's number from 1, a run of three or more as a range: a miss with its closest region, from one search of 2,097,152 UTF-16 code units that the call's misses share, a count that differs with the lines that matched, edits whose matches overlap, an edit's own refused input, a path no mount holds, a read-only mount, a generated file (by the rule `edit` refuses one by), a file it can't edit, and edits naming files in more than one mount.
  - Every path is first settled with disk, in one pass, as `edit` settles its one, and a refusal says what that pass took in. Then every file is read and planned, and every entry set in one record of the store, with nothing awaited between, so no other call, pass or branch change moves the tree between a file's read and its set, and a store that fails as it sets them sets none.
  - On a mount with `autoMaterialize`, disk can still refuse a file once every edit is stored. The answer then leads with the fact that every edit is stored, so the call mustn't be sent again, and names each file disk refused, with its push's reason. A call that fails after its entries are set says so too.
  - The answer gives each file's `size`, `replacements`, `edits` and `note`, and `changed`, each edit's first changed region, numbered. Every answer is held to the call's `resultMaxChars`, or with none to 24,000 characters: past it, regions are named by their lines, a file is listed without its notes or edits' numbers and then counted rather than listed, a refusal names its problems before it explains any, and its last line counts what it left out. From 1,000 characters, the least a residence or an agent can set, a refusal names at least its first problem; under about 300 characters, which a strategy's per-message bound can set, its head and last line alone can pass the cap.
