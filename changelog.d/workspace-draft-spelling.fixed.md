- On a disk that folds case, as macOS's does by default, a path that disk has nothing for takes the spelling of a workspace entry it equals in lower case, so a draft that isn't on disk yet has one name too. A `write` of `work/src/NEW.txt` where the workspace holds the draft `src/New.txt` now writes that draft, as the disk will once it's materialized, and `read work/src/new.txt` finds it; a directory works the same way. Two drafts that differ only in case used to be two entries for one file: a materialize wrote one and skipped the other, a forced one wrote the second over the first, and two directory drafts became one disk directory whose files the next pass moved under its spelling. A path that names a workspace entry exactly keeps that spelling, so an entry that disk lists in another spelling, such as a draft beside a file made on disk in another case before the draft was materialized, is read, synced, materialized and deleted by its own path. Names are compared in lower case without Unicode normalization, so drafts that differ only in normalization form stay two entries. Spelling a path disk has nothing for reads the workspace's entries under its directory, so on macOS a script that creates thousands of new files under one large directory pays that once per file. On a disk that tells case apart, every answer is as before.
