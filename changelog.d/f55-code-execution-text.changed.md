- `code_execution`'s result now reaches the model as text, where it was one line of JSON with the script's output escaped inside it. How the script ended comes first, as `exit code: N` and, when the call's `time_limit_ms` was capped, the time-limit note; then the script's stderr, then its stdout, each under a label. A result past the agent's inline cap (`tool_result_inline_max_chars`, 24,000 characters by default) is cut a stream at a time to each one's head and tail, around a count of what was cut, at a line's end where one is near: stderr keeps up to a third of the room, or more when stdout needs less. So the exit code and the end of stderr, which holds a traceback and the reason a stopped script gives, stay in view however long stdout runs, where a long stdout used to push them past the cut. The whole output goes to the workspace file a long result spills to, and the result's last line says where.
