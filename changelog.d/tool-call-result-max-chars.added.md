- **Module authors:** a tool call now carries `resultMaxChars`: how long its result may be and still reach its caller whole, measured as the framework stores it (an error's text, or a success's `data` as JSON, with a content array taken as its text). A tool that pages or budgets its answer can stay under it.
  - A model's call carries the agent's effective inline cap: its `tool_result_inline_max_chars` setting, else the residence's `toolResultInlineMaxChars`, else the default 24,000, lowered to the strategy's per-message bound. Past it, the framework writes the result to a workspace file and stores its start, or only its start where no file can be written. A `utils` run of a utility and an operator's puppet call carry the same.
  - A call from a running `code_execution` script carries the script's limit, 5,000,000 characters, past which the result the script receives is cut.
  - A call whose caller takes the module's result in process (`ModuleContext.callTool`, a subagent's `executeToolCall`) carries none.
  - The module registry now passes every field of a call on to the module. It used to pass `id`, `input` and `callerAgentName` alone.
