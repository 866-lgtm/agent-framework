- **Operators whose mounts hold symlinks inside them:** on a mount that doesn't set `followSymlinks: true`, the default, a file reached through a symlinked directory inside the mount is no longer read, written or synced through the link. A file a host reads from disk behind such a link, such as an agent's instructions file, is refused, with a refusal naming the link and where it leads. To keep using it, set `followSymlinks: true` on that mount, or move the file so that no directory on its path is a link. Unchanged: a link leading out of the mount, and a file that is itself a link, are refused as before.
- **Hosts and module authors choosing advice by a disk read's code:** `readFileFromDisk` refuses a link among a path's directories with a new code, `parent_symlink`, which `WorkspaceReadErrorCode` gains. A link leading out of the mount keeps `escape`, and a file that is itself a link keeps `symlink`.
