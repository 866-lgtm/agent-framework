- `quiesce()` now writes the queue of deferred context writes before it changes anything, or fails, and a write of that queue that fails elsewhere is reported where an operator looks.
  - **A write deferred behind a turn still alive** before the host quiesced was held in memory only. `quiesce()` didn't write the queue, so when its drain timed out with that turn alive, a crash before the queue next changed lost the write. `quiesce()` now writes the queue first, before the host-mode record, on a first call and a repeat alike. A write that fails rejects with the host as it was, and so does a queue over the cap, with an error that names the cap and how to get under it.
  - **A write of the queue that fails elsewhere,** such as when a context write is deferred while quiesced, still keeps the queue in memory, since the write's source has already been answered, and the queue's next change writes it again. It used to be logged and nothing more. It now raises a `deferred-writes` ops alert at a run's first failure, and a line is logged when a write succeeds again, which ends the run. A queue over the cap raises the same alert, and its line is logged once a run rather than once a process.
  - **The cap is unchanged:** when the queue's JSON is longer than 4 MiB, counted as the string's length, its record isn't written at all and keeps what it last held.
  - **Without a recovery file,** the store is the record, and the queue's write wasn't synced, so a crash could lose it. The store is now synced after the write, as it is for the host-mode record, and a sync that fails counts as a failed write.
