- A context budget the agent was running at comes back at once after a restart, when it still fits (context-manager #162). Before, every restore of a lower budget paced a new descent from the recipe's budget, so until the first compile settled it the agent reported `converging` and planned at the recipe's budget. The persisted runtime settings now carry `contextBudgetReachedTokens` beside `contextBudgetTokens`: the budget the agent's last compile planned at, written when a compile fits at the record's budget (a paced descent's settle included) and withdrawn when the context manager refuses that budget as over budget. An immediate change carries none until a compile fits at it. At boot, a record whose two values match is applied through the immediate path, but only if the preflight says the budget fits now. The preflight plans the stored context as the context manager will, so it sees a new `maxTokens` or strategy configuration a restart brings, and a context that grew while the agent ran at another budget; the system prompt and tools are outside the context manager's budget. Otherwise, and for a record without the field (a descent still running at the stop, or a record from an earlier release) or with a value for another budget, it restores paced, as before, with a log line when a reached budget no longer fits. A boot restore still never refuses a persisted budget. A patch can't set the field, an invalid value is ignored with a log line, and a record holding nothing else restores nothing.
- The runtime settings snapshot (`getAgentRuntimeSettings`, `agent_settings` `get`) reports `effectiveContextBudgetTokens`, the budget compiles plan at now. While a lower budget converges, it is still the budget the descent started from; `contextBudgetTokens` stays the budget the agent is set to. Code that builds an `AgentRuntimeSettingsSnapshot` itself, such as a test double, adds the field.
